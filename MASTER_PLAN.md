Repository Workflow

Every contribution should follow this workflow:

1. Understand the current project phase.
2. Read the relevant documentation.
3. Make changes only within the scope of the current milestone.
4. Review for consistency with existing documentation.
5. Commit changes with clear commit messages.
6. Push changes to the remote repository.

Documentation should always remain synchronized with project decisions.

---

Documentation Reading Order

Anyone joining the project should read the documentation in the following order:

1. "PROJECT_CONTEXT.md"
2. "MASTER_PLAN.md"
3. "docs/15_AI_Onboarding.md"
4. "docs/16_Project_Constitution.md"
5. "docs/14_Current_Status.md"
6. Current working document

This ensures contributors understand the project before making changes.

---

Project Rules

The following rules apply throughout the project:

- Documentation precedes implementation.
- The repository is the single source of truth.
- Major decisions must be documented before code is written.
- Avoid unnecessary complexity.
- Prefer modular and maintainable designs.
- Keep documentation current with project progress.
- Record important architectural and product decisions in the appropriate decision logs.
- Review existing documentation before proposing new ideas.
